## Findings and changes

1. **High: training could overwrite raw CSV data.** `run_pipeline.py` previously generated synthetic OULAD-schema data on every run. Generation now requires `--generate-synthetic`; otherwise the script checks that all eight required raw CSVs exist and preserves them.
2. **High: missing model produced a fabricated risk score.** `gnn/predictor.py` previously returned a fixed 0.78/high-risk response when model artifacts failed to load. It now raises an error. `/api/health` reports `degraded` without the model and `/api/ready` returns HTTP 503 until artifacts are loaded.
3. **High: student API access scope differed from MVC.** `PredictionsApiController` now filters student lists and checks access to detail/consultation requests. This change predates this audit turn and remains in the working tree.
4. **High: unknown student IDs mapped to another node.** `explainer.resolve_node_idx` previously clamped absent IDs to the first or last graph node. It now raises `ValueError`; prediction and explanation GET endpoints return 404. Regression tests cover this behavior.

## Recognition quality interpretation

- The label is `Fail` or `Withdrawn` in `studentInfo.final_result`; it is an end-of-course outcome, not a verified intervention need.
- Current raw CSVs are generated by `OuladDataLoader.generate_synthetic_oulad_sample`. Reported benchmark metrics, including temporal early warning, measure synthetic-data performance only. They do not establish accuracy on a real institution or on the original OULAD distribution.
- The stored benchmark shows Logistic Regression test ROC-AUC 1.0 versus HGT 0.9741; the present evidence does not justify claiming GNN superiority.
- Student-level stratified train/validation/test masks and train-only feature scaling are present. A future real-data evaluation should additionally split by cohort or presentation date, check probability calibration and subgroup error rates, and report confidence intervals.

## Saved-model evaluation performed

Run `ai-service/.venv/Scripts/python.exe ai-service/evaluate_recognition.py` to regenerate `ai-service/recognition_evaluation.json`. The script loads the saved static and temporal checkpoints, verifies that graph labels and CSV test masks agree, and evaluates only the held-out test nodes. It reports precision, recall, ROC-AUC, Brier score, observed versus predicted risk, bootstrap recall intervals, and gender/course subgroup results for weeks 2, 4, 8, 12, and 16.

On 45 synthetic test records (29 positive), static HGT recall was 0.897 (bootstrap 95% interval 0.774–1.000), precision 0.929, Brier 0.100. Temporal week 2 recall was 0.793 (0.640–0.929), precision 0.852, Brier 0.185. Week 16 recall was 1.000, precision 0.879, Brier 0.080. These intervals are wide because the test set is small. Subgroup figures in the JSON are descriptive only; small group sizes cannot support fairness claims.

The dataset has a single synthetic presentation, so a meaningful future-cohort split cannot be run. A real-data evaluation must use distinct presentations or academic terms, preserve temporal feature cutoffs, and obtain permission to use the student records.

## Literature-driven correction (2026-11-17)

See `knowledge-vault/gnn-ai/nghien-cuu-bo-hoc-doi-chieu.md` for primary-source links and verification of each user-provided study. Original OULAD has VLE activity but no physical attendance table; UCI's “Daytime/evening attendance” is a study schedule category, not an attendance percentage. Accordingly, `studentAttendance.csv` and its nine-session values are synthetic project extensions. `build_heterogeneous_graph` no longer generates or overwrites raw data, even with `force_regen=True` or fewer than 250 students. The saved-model report now separates `Fail` from `Withdrawn`: in the 45-record synthetic test set, static HGT flagged 13/14 Withdrawn cases and week-2 temporal HGT flagged 11/14. These are descriptive subgroup counts for a model trained on the combined `Fail`/`Withdrawn` label, not dropout-specific validation.

## Deployment limits and next work

- Docker server did not respond to `docker info` during this audit; no container deployment was verified.
- The FastAPI service was tested through TestClient, not as a running process behind ASP.NET Core. Ollama and PostgreSQL integration were not exercised.
- FastAPI model and mutation endpoints have no service authentication in `main.py`. Restrict network exposure and add service-to-service authentication before production use.
- ASP.NET Core still uses hard-coded demo accounts, and `GnnAiClientService` uses mock student data as a fallback. Remove or clearly gate those behaviors before real student records are introduced.
- The training artifacts were checked by tests, but the full training run was not repeated; benchmark values therefore remain historical artifacts, not independently reproduced in this audit.

## Reproduction

From the repository root: `ai-service/.venv/Scripts/python.exe -m pytest ai-service/tests -q` and `dotnet build GNN-EduGuard.slnx --no-restore`. To train on existing CSVs, run `python ai-service/run_pipeline.py`. To intentionally regenerate synthetic data, add `--generate-synthetic`.
